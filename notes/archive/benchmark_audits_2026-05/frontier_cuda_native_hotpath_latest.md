# Frontier CUDA-Native Hot Path Audit

This audit is static. It records which canonical decode components are truly custom CUDA today and which are still PyTorch/ATen-heavy.

## Summary

- Custom CUDA components: `5`
- Mostly native but still ATen/PyTorch-dependent: `2`
- PyTorch/ATen hot-path components: `3`
- CPU/Python accounting-only components: `0`
- Diagnostic native components not yet canonical: `3`
- Full CUDA-native production gate: `blocked`
- Blocking components for full native gate: `5`

## Full Native Blockers

These components must become promoted custom CUDA kernels before the backend can be called fully CUDA-native.

- `Paged K-PQ score fullscan`: Fuse score generation with rank-prefix materialization without changing stable/tie-sensitive ordering.
- `Rank-prefix candidate ordering`: A partial top-k/prefix kernel, or PQ score-generation plus prefix fusion, specialized for heads<=4, the largest partial budget, and canonical tie/nested-prefix behavior.
- `Exact-K refinement logits`: Profile and, if positive, promote sparse exact-K refinement; otherwise replace the remaining dense PyTorch matmul with a better fused all-KV-head sparse exact score-grid kernel.
- `V-PQ sidecar and residual/error stats`: Validate/promote native sealed-page V-PQ sidecar construction, then remove remaining grouped packing.
- `Grouped tensor packing`: Single all-KV-head native entry point or preallocated grouped output buffers written by earlier kernels.
