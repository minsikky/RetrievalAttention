## 2026-07-06 Scan-Floor Negative Results: Page Pruning and Global PQ Codebook

Two attacks on the selector-scan floor (codes 4B/token + per-page codebooks ~11.6B/token amortized at page 5632) were implemented in `run_joint_kv_budget_policy_eval.py` and are NEGATIVE at the canonical operating point. Both remain in the runner behind flags for reproduction.

- `--page_scan_frac F` (+ `--page_coarse_block B`): rank sealed pages by max PQ score (oracle order = tight envelope of any stored per-page bound), PQ-scan the top pages covering F of indexed tokens, coarse-tier the rest. Three variants all failed at 32k/h0/thr 0.002 (canonical `~4.5 MB`, relL2 `~0.0019`): page-mean logits+values relL2 `0.18` at F=0.5; block-mean (512/128) identical after fixing a `sqrt(d)` tail-logit scaling bug — still `0.13`; logit-only coarse tier (per-token V-PQ kept) `0.128` at F=0.5, `0.025` at F=0.75. Root cause: the accepted selection is `~30-40%` of context and spatially spread — EVERY page contains needed tokens, so page-skip selection loses needles regardless of the tail model. Conclusion: selection needs global per-token scoring; scan savings must come from cheaper scoring or less frequent scanning, not skipped regions.
- `--global_pq_codebook` (+ `--global_pq_subbits`, `--global_pq_sample_rows`): one shared sample-trained codebook replacing per-page codebooks (SRAM-resident on a chip; scan reads codes only). Quality holds (relL2 `0.00179` vs `0.0019`) but the coarser ranking makes the adaptive ladder over-escalate: selected `32k/38.8k` tokens, step `10.05 MB` at 8 bits; `24.5k` and `8.47 MB` at 10 bits/32k samples — both far above canonical `~4.5 MB`. Per-page (locally adaptive) codebooks are load-bearing for ranking fidelity on real key distributions. Conclusion: keep per-page codebooks; amortize their read via temporal reuse instead.

## 2026-07-05 Progressive/Bit-Plane Precision K/V Reads (CPU, in flight)

Bit-plane storage means the low tier is a strict subset of the bytes (no extra storage), and two split non-contiguous streams are GPU-unfriendly => custom-chip angle.

## 2026-07-05 Temporal Selection Reuse (CPU, in flight)

- Motivation: the per-decode-step selector fullscan re-reads PQ codebooks+codes (~15.6B/token: 4B codes + ~11.6B/token amortized codebooks at page 5632) even though consecutive steps' selections overlap heavily. A chip can hold the last scan's ranked candidate list + stale PQ logit row and rescan only every S tokens — sequential cross-step state that GPUs handle poorly (custom-chip angle).
- Trace structure caveat discovered: `real_qkv_llama31_l16_6838_g131072_q288_window32_graphall_s16.npz` has ONE query per decode value (288 total), spaced 16..2065 tokens apart (geometric within each octave), with consecutive +1 pairs only at 500/501, 1000/1001, ..., 64000/64001. So the experiment measures overlap/quality as a function of *staleness gap*, not fixed rescan period; the gap spectrum the trace provides is exactly the interesting range.
- Runner changes (`run_joint_kv_budget_policy_eval.py`):
  - `--temporal_cache_stats`: along any trajectory, per accepted step records vs the previous same-head query: `temporal_gap_tokens`, accepted exact-K/V set sizes, new-token counts, and prev-overlap fractions. Measures the hit rate of a token-keyed on-chip K/V row cache with zero behavior change.
  - `--temporal_reuse_max_stale S`: frozen-selection mode. While position is <= S tokens past the last rescan: reuse that rescan's ranked list + stale PQ logits + frozen page index; tokens appended since stay resident in an extended base (charged as exact-K via selected count); selector charge becomes a stale-state reread (2B/token logits + 4B/candidate indices, ~2.25B/token vs 15.6B/token fullscan). Requires fullscan + baseline proxy + global_residual_risk (two-pass pass-1 rides the fullscan that reuse skips; composition deferred).
  - Sealed-page build cache: identical (dynamic_start, sealed_end) => reuse pages bit-exactly across steps (same key prefix, same seed), patching only `indexed_end`. Cuts k-means rebuild cost ~12x for the 288-query all-decode sweep.
- Smoke (d500..549, h0): stats fields correct (gap 1/16 rows show k/v churn == appended tokens only at 7k context); reuse mode reuses at stale 1/17/33, rescans at 49 with S=40; reused-step relL2 unchanged vs canonical at tiny context.

## 2026-07-05 Two-Pass Threshold Exact-V (Tiled-Compatible Selection)

- Motivation: the canonical frontier algorithm cannot run FlashAttention-style tiled because exact-V selection is a global top-k over `risk_i = p_i^2 * err_i`, which needs the full probability row retained to scan end. Prior tiled attempts all failed for diagnosable reasons: local block quotas lose global ordering (`51252564`), streaming running-top-k pays read-union waste (`51269652`), and dropping `p_i` is strongly negative (`51266285`).
- New variant `two_pass_risk[_f<mult>]` in `run_joint_kv_budget_policy_eval.py`: pass 1 rides the selector fullscan stream (PQ logits for non-resident tokens, exact logits for resident base tokens) and keeps only per-V-budget cutoff values of unnormalized log-risk `2*logit + log(err)` via a running c-th-largest heap; pass 2 commits exact-V tile-locally by comparing the true mixed log-risk against the scalar cutoff. No survivor list, no stored probability row, no read-union. `f<mult>` scales the cutoff rank (safety margin sweep). Accounting charges actual exact-V reads plus one extra pass-1 read of V-PQ error metadata; state MB (when included) is the cutoff heap only.
- With perfect PQ scores the rule reduces exactly to global residual-risk top-k, so quality loss isolates the cutoff-estimation error.

## 2026-07-05 Bounded-Lookahead Confidence Diagnostic

- Motivation: on hardware, each adaptive-budget confidence test must physically read the next budget band's exact rows before it can decide to stop (K bands are ~20% of context each), so naive lookahead dominates physical overhead when mean iterations are low. Idea: certify `delta < threshold` from compressed-domain upper bounds and skip the read when certified.
- Added `--lookahead_diagnostic` to `run_joint_kv_budget_policy_eval.py` (`LOOKAHEAD_DIAGNOSTIC=1` in the wrapper). It does not change policy decisions; it records, along the canonical trajectory, per-test certification for variants `charge_all` (naive hardware, no bounds), `cs` (strict Cauchy-Schwarz K-logit bound from per-token K-PQ reconstruction residual-norm sidecars, charged at 2B/token), and `rms1/rms2/rms4` (calibrated typical-case `||q||*r/d` estimates). All bound variants share the strict V-band bound `sum(p_i * ||v_i - vhat_i||)`. Outputs per variant: wasted lookahead MB (bands read for tests that did not lead to escalation), hardware-style step MB, certification counts, and false-certify counts (bound certified but true delta above threshold; nonzero values invalidate that variant's stopping semantics).
- The K bound covers the logit-upgrade effect only, not second-order V-mask recomputation; false-certify counts are the guard for that approximation.
- Local smoke (d500/1000 h0): naive lookahead adds about `+21%` step MB even at tiny contexts; bounds certify a subset of tests and halve waste with zero false certifies.
- Submitted on `standard` with account `zhengya0`: long-subset job `52950622` (heads `0,8,16,24`, decodes `32000,128000`) and full all-head job `52950623`, both `global_residual_risk` only, dense thresholds. Output root: `attention_efficiency_result/joint_kv_lookahead_bounds_20260705`.
- v1 long-subset result (`52950622`, completed): strict/L1 bounds are useless at long context. Certification rate is `0%` for `cs` and all `rms` variants at 32k/128k, so naive hardware lookahead stands at `+58-60%` over logical step MB (`11.355 -> 17.95 MB/head-query` at threshold `0.002`; `14.73 -> 23.08` at `0.001`). Zero false certifies (bounds valid, just loose). Diagnosis: L1/triangle bounds scale with band token count while true deltas cancel like `sqrt(n)`; at 27k-token bands the bound overestimates by `~50-100x`.

## Active Goal Statement

End state: one benchmark-ready canonical GPU implementation of the current CPU frontier decode algorithm. It keeps dense prefill, approximates decode only after sealed PQ pages are active, matches CPU frontier semantics, and is fast enough to run real dense-vs-frontier task benchmarks.

Canonical algorithm semantics to preserve:

- Prefill attention is dense. Prefill may build/update PQ sidecars, but it must not use sparse/frontier attention.
- Decode uses the CPU frontier algorithm: paged K-PQ fullscan selector, raw K-PQ approximate logits, candidate ranking, exact-K refinement, mixed exact-K/K-PQ logits and probabilities, adaptive K/V output-stability confidence, global residual-risk exact-V selection, and V-PQ reconstruction for non-exact V rows.
- Exact V selection is global residual risk: `risk_i = p_i^2 * V_PQ_error_stat_i`, where `p_i` comes from the mixed exact-K/K-PQ probability distribution.
- Accepted K budgets, accepted V budgets, selected-token counts, logical MB/query, attention outputs, and o-proj outputs must match the CPU reference within parity tolerance.
- Any change to selector scoring, calibration, ranking, budget ladder, confidence/stopping rule, probability construction, exact-V rule, V-PQ reconstruction, or dense-prefill/decode-only scope is a separate algorithm variant, not a canonical optimization.

Implementation approach:

- The benchmark decode hot path must be fused/native CUDA. The target is not a PyTorch-heavy or hybrid PyTorch+CUDA implementation.
- Native CUDA should own decode-critical work: K-PQ scoring, candidate ranking/top-k, exact-K logits, mixed probability construction, adaptive K/V confidence, residual-risk ranking/prefixes, V-PQ aggregation, and final output construction.
- PyTorch is allowed for model orchestration, tensor allocation/lifetime, QKV/O-projection plumbing, extension launch glue, lightweight metadata setup, assertions, reporting, and offline parity/debug checks.
- PyTorch must not dominate the decode loop through repeated hot-path `topk`, `sort`, `gather`, `scatter`, `softmax`, matmul, masking, prefix-sum, or per-budget tensor materialization.
- Dense-logit simulator paths, PyTorch-heavy paths, and partially native paths are useful diagnostics, but they are not the final benchmark path unless profiling proves the remaining PyTorch work is outside the decode-critical path and semantics still match the CPU reference.

Performance goals:

- Overall runtime target: canonical frontier decode should run within `2-3x` dense decode on representative active-path benchmarks while preserving semantics.

## Active Algorithm

Canonical frontier path as of 2026-05-25:

- Dense prefill.
- Decode-only paged-PQ selector sidecars.
- Decode query scores all tokens with K-PQ, ranks tokens, and refines selected tokens with exact K.
- Adaptive K and V budgets selected by output-stability confidence, not fixed mass.
- Mixed probabilities are formed from exact selected-K logits plus raw K-PQ tail logits (`a=1,b=0`; no affine calibration).
- Exact V rows are selected globally by residual-risk, not selected-set mass:
  `risk_i = p_i^2 * V_PQ_error_stat_i`.
- Non-exact V rows use V-PQ reconstruction.
- Logical frontier MB accounting separated from physical GPU simulator MB.

Current canonical trace policy as of 2026-05-28:

- K budget grid is relative: `10%,30%,50%,70%,90%,100%`.
- V budget grid is relative: `5%,10%,20%,40%,60%,80%,100%`.
